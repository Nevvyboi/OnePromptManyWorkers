i.
Act one

The Prompt

The smallest unit of the whole thing, and the most misunderstood.

The atom

A model is just a function.

Text goes in. Text comes out. No memory of a moment ago. No hands. No way to check its own work.

A prompt is you calling that function.

String reply =
  model.chat("summarise this");

// text in → text out
// no memory. no hands.
// ask twice → two answers.
The ceiling

A raw prompt hits three walls.

WALL 01

No memory

Every call starts from zero. It forgot the last sentence the instant it finished it.

WALL 02

No hands

It can describe sending the email in beautiful detail. It cannot send it.

WALL 03

No proof

It sounds equally sure when it's right and when it's making things up.

Act two

The Agent

Same model. Now it can remember, act, and try again.

The equation
modelthe brain
+
toolsthe hands
+
a loopthe magic

That's an agent. Everything else is decoration. The loop is where the magic actually lives.

The whole trick

Reason. Act.
Observe. Again.

The model doesn't answer once. It works in a loop until the job is actually done, checking its own output along the way.

Take away the loop and you're back to a chatbot.

The Infrastructure

What you actually need underneath, and why the JVM is a great place to put it.

The anatomy

Five layers under every agent.

runtimeThe model host. Ollama, running Qwen on your machine.
orchestrationThe loop & wiring. LangChain4j or Spring AI.
toolsThe hands. Java methods the model may call.
memoryThe notebook. What it carries between turns.
structureTyped output. Answers as objects, not prose.
The obvious question

Why Java?

Because the systems your clients trust with real money already run on the JVM. The agent should live next to the business, not in a Python service bolted on the side.

Behind Spring Security. Inside your transactions. Beside your data.

LangChain4jagents, tools & AI Services, the idiomatic way
Spring AIthe same, wired into Spring Boot
the pointtype-safe, testable, production-grade agents
The model, tonight

Qwen. Local. Free.
Never leaves the room.

Ollama serves the model from this laptop. No cloud call, no per-token bill, no data leaving the building. That last part is what your regulated clients care about most.

Live code · 1 of 2

One interface. Every worker.

// No implementation. The annotations are the program.interface Worker {  @SystemMessage("You are a {{role}}. Answer only from that one view.") @UserMessage("{{task}}") String work(@V("role") String role, @V("task") String task);}

Same interface for the Engineer, the Marketer, the Lawyer. Only the role changes.

Plan → dispatch → synthesize.

Plan plan = planner.assemble(prompt); // 1 prompt → a crew var notes = new StringBuilder();for (var a : plan.crew()) { // fan out String answer = worker.work(a.role(), a.task()); notes.append(a.role()).append(answer);} String result = synthesizer.synthesize(notes); // fan in

Every agent is the same local model. The only difference is the instructions.
